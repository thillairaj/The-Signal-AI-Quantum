Six things a leader should hold on to

The threat is already running

Harvest-now-decrypt-later collection does not wait for a quantum computer. Every day of delay adds intercepted traffic to someone else's archive, and the data with the longest secrecy life is the data already at risk.

The standards are finished

NIST finalised FIPS 203, 204 and 205 in August 2024. The question is no longer which algorithms to adopt, but how fast your estate can inventory, prioritise and migrate to them.

Inventory before action

You cannot migrate what you cannot list. A cryptographic inventory and CBOM come first in every credible programme, and discovery always finds more than the architecture diagrams promised.

Prioritise by data lifetime

Mosca's inequality turns an unknowable date into arithmetic: secrecy lifetime plus migration time versus time to a quantum computer. Sequence the programme by that arithmetic, not by which system shouts loudest.

Hybrid first

Running classical and post-quantum cryptography together protects you if either one holds. Browsers and CDNs already default to hybrid key exchange, so your external connections can move this quarter.

Agility is the real deliverable

Algorithms will change again. A migration that leaves inventory, abstraction and automation behind has bought a permanent capability; one that hard-codes the new algorithms has only rented time.

A leader's PQC migration checklist

Start this year

  • Commission a cryptographic inventory and CBOM
  • Classify data by required secrecy lifetime
  • Enable hybrid PQC key exchange on external TLS through your CDN or load balancer
  • Get PKI and HSM vendor roadmaps in writing
  • Name the programme owner and stand up a Crypto Centre of Excellence
  • Add PQC and crypto-agility clauses to procurement templates

Run the programme

  • Migrate code signing first if you ship firmware
  • Sequence PKI and certificate migration ahead of dependent systems
  • Pilot PQC on one partner VPN tunnel and measure everything
  • Adopt 2030 deprecation as the internal deadline for exposed systems
  • Test interoperability before each phase, with rollback ready
  • Report inventory coverage, long-life data protected and milestones to the board annually

An honest note

Nobody knows when a cryptographically relevant quantum computer arrives, and anyone selling certainty, in either direction, is selling. The case for acting now does not need the date: harvested data plus multi-year migration lead times make the arithmetic work on their own. Two cautions in closing. QKD is not a shortcut around this programme, as the major security agencies keep pointing out. And a vendor quantum-safe label means nothing until it names a FIPS standard, a parameter set and a certification.
